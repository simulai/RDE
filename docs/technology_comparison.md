## 0. 本文档的定位与理论边界声明

按任务书第 9 节：**技术选型暂不锁定**。本文件只做方案比较，不宣布任何方案已被证明最优，也不预设「必须使用图数据库」。显式图结构未必是唯一实现方式（理论边界第 9 条），因此本比较把「图存储」仅作为候选之一，与关系型、文档型、纯文本日志方案放在同一张表上衡量。

本文件遵守任务书第 8 节全部理论边界，特别地：

1. 下文任何性能数字均为**量级估计与工程常识**，不是本仓库已测得的实验结果；未做基准测试前不得当作结论引用。
2. 「推荐」一律表述为**待验证的工程判断（假说 H-TECH-001）**，其成立依赖于第 6 节的回退条件与重新评估触发条件。
3. 选择某个存储技术不增强任何命题的真值，也不使任何研究结论更正确（边界 3/4/5/6）。
4. 第一阶段的最小原型约束（纯 Python、无外部服务）是**当前阶段的工程约束**，不是对其他方案优劣的终局裁决。

## 3. 逐维度比较

### 3.1 超边（多前提多结论）表达能力

RDE 的核心结构是超图：一条推导/证据边可同时挂接多个前提与多个结论，且允许多条并行证明路线共享同一证据（见 `docs/graph_semantics.md`）。

| 方案 | 表达方式 | 评价 |
|------|---------|------|
| A | 边对象直接含 `premises[]`、`conclusions[]` 数组；`schemas/` 下 JSON Schema 校验 | **天然表达**，无阻抗失配；校验依赖 schema 而非存储引擎 |
| B | `edge` 表 + `edge_endpoint(edge_id, node_id, role)` 关联表；`role ∈ {premise, conclusion}` | 关系型建模 n 元关系的标准做法，表达完整；写入需应用层保证一致性 |
| C | 同 B；可用数组列/JSONB 简化 | 表达完整；JSONB 提高灵活性但削弱约束力 |
| D | NetworkX 核心是成对边（DiGraph/MultiDiGraph），**无原生超边** | 需星形展开（超边→中间节点）或团展开做转换，转换本身是待验证的映射，非无损默认 |
| E | Neo4j：需将超边实体化（reification，中间节点/关系分组）；RDF：n 元关系需 reification 或空白节点模式 | 可表达但**均需间接编码**；OWL 的表达力面向本体分类，不等价于推导超边语义 |
| F | 事实以数据形式存储，形状任意 | 表达自由度高；参照其「事实不可变」设计而非其运行时 |

**小结（非结论）**：A/B/C 对超边是直接表达，D/E 是间接表达。超边需求本身不构成选择图数据库的理由——恰恰相反，本项目最重要的结构（多前提多结论）在关系模型中是成熟模式。

### 3.2 事件溯源 / 追加日志适配度

RDE 要求：所有研究操作产生不可变事件，当前知识状态由事件日志重放重建，禁止覆盖历史（`docs/event_sourcing.md`）。

| 方案 | 适配度 | 说明 |
|------|--------|------|
| A | **最高** | JSONL 每行一个事件，天然只追加；文件系统 append 即是存储语义 |
| B | 高 | `events(seq, ts, type, payload, prev_hash)` 表，追加写；可用触发器禁止 UPDATE/DELETE；仍是日志建模 |
| C | 高 | 同 B，另有 WAL、逻辑复制等企业级保障；但事件语义仍需自建 |
| D | 无 | NetworkX 是内存结构，不提供日志语义；只能作为「日志重建后」的分析视图 |
| E | 低-中 | Neo4j 有事务日志但不是领域事件日志；RDF/OWL 无追加事件范式（有 PROV-O 等溯源词汇，属建模层） |
| F | 原生最高 | Datomic 类系统把「不可变事实 + 事务日志」作为核心抽象，是该范式的成熟先例 |

### 3.3 版本与时间点重建

| 方案 | 时间点重建方式 | 说明 |
|------|---------------|------|
| A | 重放 JSONL 至目标 `seq`/时间戳；可加周期快照 | 语义最直接；重建成本 = O(事件数)，需快照缓解 |
| B | `WHERE seq <= :t` 的窗口查询 + 折叠；或按版本表 | 单文件内完成，递归 CTE 可参与重建期的依赖计算 |
| C | 同 B，支持 bitemporal（事务时间/有效时间）双轴建模 | 能力更强，但复杂度与运维同时上升 |
| D | 从日志重建到内存后按截止点截取 | 作为分析层可行，仍依赖 A/B/C 提供日志 |
| E | Neo4j 无内建双时间版本；RDF 版本化需自建命名图/版本词汇 | 需大量自建，等于把版本系统重新实现一遍 |
| F | `as-of` / `since` / `history` 查询为原生能力 | **概念上最贴合**；但引入外部服务与许可成本 |

### 3.4 依赖影响分析的遍历性能

RDE 的影响分析：基础节点变化 → 下游可达集 → 按证明路线聚合（`docs/dependency_propagation.md`）。这是有界深度的可达性遍历 + 聚合，不是任意图算法。

| 方案 | 遍历方式 | 量级估计（未实测） |
|------|---------|-------------------|
| A | Python `dict` 邻接表 + 迭代 BFS/DFS（避免递归深度限制） | 10⁴–10⁵ 节点、10⁵ 边量级内通常可接受；超出需索引/增量计算 |
| B | 递归 CTE `WITH RECURSIVE` + `(from,to)` 索引 | 中小规模可行；深/宽遍历与递归深度需实测；单写者不构成分析瓶颈 |
| C | 递归 CTE；可选 pgRouting（最短路/可达）、Apache AGE（Cypher） | 大规模并发查询更强；但引入扩展依赖，**不作为前提** |
| D | NetworkX 内存遍历（`descendants` 等） | 分析原型验证最省事；需全量载入内存，不承担持久化职责 |
| E | Neo4j 索引无关相邻（index-free adjacency）深遍历 | 大规模深遍历有理论优势；**本项目第一阶段尚未出现该规模证据** |
| F | 需自行实现图遍历 | 时间点查询强、遍历弱 |

**小结（非结论）**：遍历性能优势只有在规模与频率成立时才有意义；第一阶段尚无实测负载数据，任何「图数据库更快」的表述在本仓库中都属于未经验证的假设。

### 3.5 可审计性（diff / 回放 / 哈希链）

| 方案 | diff | 回放 | 哈希链 |
|------|------|------|--------|
| A | JSONL 文本逐行 diff，与 Git/代码审查工具链天然兼容 | 全量重放即可，可复现性最强 | 每事件含 `prev_hash` 即构成链，实现是纯 Python 小段代码 |
| B/C | 二进制文件不可直接 diff；需导出为 JSONL/SQL 文本再审 | 可回放；审计常靠触发器 + 导出 | 可加 `hash` 列，语义与 A 相同 |
| D | 不适用（非持久层） | 取决于上游日志 | 不适用 |
| E | 图数据与文本 diff 隔离较远 | 回放需外部日志方案 | 需自建 |
| F | 数据即事实，可导出文本 | 原生 history | 事务日志天然有序 |

RDE 原则第 8 条「历史记录不可被静默覆盖」与第 1 条「正确性优先于效率」共同指向：**审计链应先独立于任何重型服务存在**。A 方案的哈希链 + 全量回放是验收标准「同一日志重建同一状态」「决策可回溯」的最小实现路径。

### 3.6 并发与协作

| 方案 | 并发模型 | 协作含义 |
|------|---------|---------|
| A | 单写者（文件 append + 应用层锁）；多读者读快照 | 追加型日志的合并冲突极低；多人协作靠「各写各的日志分支 + 合并校验」，合并语义**待设计** |
| B | 单写多读（WAL 模式改善读并发） | 单人/单进程研究内核足够；多进程并发写会排队 |
| C | 真正的多写 MVCC | 多人实时协作最强；也带来锁、迁移、权限管理成本 |
| D | 无并发语义（进程内内存） | 不参与协作层 |
| E | 服务端 ACID 多客户端 | 协作强，但需要服务器与运维 |
| F | 单写者 transactor、多读者 | 读扩展好，写仍是串行点 |

第一阶段的实际形态是「最小原型 + 单人研究内核」，A/B 的并发上限**目前不是约束**；该判断本身属于 H-TECH-001 的待验证部分。

### 3.7 运维成本

| 方案 | 运维成本（定性） |
|------|-----------------|
| A | 零：仅文件系统；备份 = 复制/`git` |
| B | 零服务：Python 标准库 `sqlite3` 内建；单文件备份 |
| C | 需安装、升级、鉴权、备份、监控的数据库服务 |
| D | `pip install networkx`（可选依赖），无服务 |
| E | JVM/服务进程、许可证（社区版/企业版）、监控；OWL 推理器另有复杂度与不可预测的推理成本 |
| F | 托管或自建 transactor，生态与许可成本 |

### 3.8 与最小原型（纯 Python、无外部服务）的兼容性

| 方案 | 兼容性 |
|------|--------|
| A | **完全兼容**（标准库即可） |
| B | **完全兼容**（标准库内建，仍是零外部服务） |
| C | 不兼容（需外部服务；可作为第二阶段后端） |
| D | 基本兼容（可选 pip 依赖；仅分析期，不进入核心正确性路径） |
| E | 不兼容（外部服务 + 运维） |
| F | 不兼容（外部服务/许可） |

## 5. 第一阶段推荐：待验证的工程判断（假说 H-TECH-001）

> **H-TECH-001（待验证，非已证明结论）**：第一阶段采用 **A + B + D 的分层组合**——
> 1. **权威数据 = 纯 Python 内存对象 + JSONL 追加事件日志**（唯一事实来源，含 `prev_hash` 哈希链）；
> 2. **SQLite 作为可选持久化/查询层**（递归 CTE 做依赖影响分析的候选实现），任何 SQLite 内容都必须能由 JSONL 日志无损重建，**不允许出现只有数据库知道、日志里没有的状态**；
> 3. **NetworkX 仅作分析与原型验证的可选依赖**，不进入核心正确性路径，不作持久层。
>
> 该判断的依据是：与任务书第 9 节「不预设图数据库必要」、验收标准「同一日志重建同一状态」「决策可回溯」、以及理论边界第 9 条（显式图结构未必是唯一实现方式）一致；并且它保持**零外部服务**与**可完全回退**。

### 5.1 为什么不是图数据库（E）

第一阶段不选择 E 的理由是**当前证据不足与成本**，而非 E 被证明更差：

- 超边需要 reification 间接编码（3.1），表达优势不成立；
- 事件溯源、审计链、时间点重建均需自建（3.2/3.3/3.5）；
- 遍历性能优势所需的大规模负载尚未出现（3.4）；
- 引入外部服务，直接违反最小原型约束（3.8）；
- 一旦引入，「图数据库是必要前提」的假设会反过来塑造架构——这正是任务书第 9 节要求避免的。

同理，C（PostgreSQL）不作为第一阶段前提；其多写并发与规模能力在协作需求真实出现之前属于过早优化。F 仅作设计参照。

### 5.2 回退条件（出现任一项即回退/降级）

| 编号 | 回退条件（可观察、可测） | 回退动作 |
|------|------------------------|---------|
| R-1 | JSONL 日志出现损坏且无法由哈希链定位与修复 | 停止以日志为唯一真相；引入 SQLite 事务写为第一真相，日志降级为导出物 |
| R-2 | 单次全量重放超过可接受交互时长（阈值待定，见 Q-TECH-02） | 引入周期快照（快照必须可由日志再生并校验） |
| R-3 | 单写者锁成为真实协作瓶颈（多进程并发写需求被确认） | 评估迁移 B→C（PostgreSQL），保持事件 schema 不变 |
| R-4 | 依赖影响分析在目标规模下超过响应预算（阈值待定，见 Q-TECH-03） | 先做增量物化/索引优化；仍不达标再评估 C 或 E |

### 5.3 重新评估触发条件（触发即重开本比较，不自动改结论）

1. 节点/边规模跨越预设量级（阈值待实测确定，见 Q-TECH-01）；
2. 出现真实的多用户并发写或跨项目联合查询需求；
3. 需要与外部系统（文献库、实验平台、机构数据）做双向集成；
4. 出现「必须用 Cypher/SPARQL/OWL 推理才能表达」的已确认需求，且 A/B 无法以可接受复杂度表达；
5. 第二阶段验收标准调整，或理论边界文档修订；
6. 任何回退条件 R-1…R-4 被观测到。

**重新评估 ≠ 自动升级**：每次触发都应产出新的比较记录与新的假说编号（H-TECH-002…），并登记到 `docs/design_risks.md`。

  定位：仪器包（带证明的递推、ball arithmetic 误差半径、完备性证书等可被 LLM
  驱动的科学软件）+ skills（markdown 协议，编码"什么叫做完了"），模型无关。
- **与 RDE 的关系（判断，非事实）**：互补分层——BootLoops 管**证据生产**的可信性
  （仪器与协议），RDE 管**知识状态演化**的可审计性（事件溯源、依赖传播、状态机）。
  假设性组合方式为"BootLoops 证书 → RDE evidence 事件（`data_ref`）"；
  **映射未设计、未验证**（Q-TECH-09）。
- **可借鉴协议清单**（记录，均未实现，逐条对应 RDE 编号）：
  1. 正对照——检查须先证明"能失败"，否则不构成证据 → RDE `falsification_conditions`
     目前仅有字段、无此语义；

  5. refusal over invention——找不到就拒绝编造、记 unknown → 与 `underdetermined` 一致。
