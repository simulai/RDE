## 0. 问题与纪律

**问题**：RDE 的最小必要结构是什么？

判据方向：删掉某模块，系统就失去研究演化能力 → 它才是候选原语；
如果某模块可以由其他模块组合实现，就不应把它列为独立公理。

纪律（与任务书一致）：

1. 不预设七个模块都是必要的；
2. 不预设它们彼此独立；
3. 先逻辑推断，再设计实验验证；
4. 每条结论标注证据等级：**推断** / **实现观察** / **实验**；
5. 测试通过 ≠ 理论成立（R-019）。

## 1. 基线候选结构

ℛ = (S, D, C, E, V, T, Π)

| 符号 | 模块 | 功能 |
| --- | --- | --- |
| S | State | 研究状态 |
| D | Dependency | 定义与依赖关系 |
| C | Constraint | 约束与证明义务 |
| E | Evidence | 证据与实验结果 |
| V | Verification | 验证与可信度判断 |

原 G1–G7 与模块一一对应，仅保留作实现层自检，不作必要性论证依据（见 §2.1）。

## 2. 方法论修正（三个前置问题）

### 2.1 循环性：G1–G7 不能当判据

G5=V 的功能、G6=T 的功能、G7=Π 的功能——"删 V 失去 G5"由定义为真。
消融判据必须从研究现象导出 → **G′ 清单**（`capability_list.md` §0）。

### 2.2 删除必须指定层次

沿用"数据结构 / 功能 / 数学性质"三分（三者不等价）：

| 模块 | 数据结构层删除 | 功能层删除 | 数学性质层删除 |
| --- | --- | --- | --- |
| S | 删状态视图/存储 | 删三维度语义 | 删"状态可由日志重建"这一性质 |
| D | 删边数据 | 删关系语义或删传播算法（二者可分） | 删依赖的传递闭包性质 |
| C | 删 proof_obligations 字段 | 删 L1/L2/L3 守卫 | 删"义务须先履行"的约束语义 |
| E | 删证据节点 | 删 sufficiency/withdraw 通路 | 删证据与主张的支撑关系语义 |
| V | 删校验调用 | 删检查逻辑（分散多处） | 删"验证依据独立于产生过程"性质 |
| T | 删事件日志 | 删状态机转移规则 | 删重放确定性（Q-004） |
| Π | （不存在） | （不存在） | （不存在） |

**结论**：不指明层次的"删除模块"结论不可比较；每轮实验必须记录删除层次。

### 2.3 T 的混装与 S 的投影（实现观察）

- 实现中 **S 不是存储，是投影**：`KnowledgeState = fold(replay, initial, events)`——
  S 是 T（日志）的函数；
- 实现中 **T 混装两样东西**：事件日志（append，审计完整性）+ 状态机（转移规则，
  合法性）。实验 6"删除 T"须拆成两个实验：删日志 / 删状态机；
- 推论：七模块在实现中的依赖方向与"并列"假设不符（详见 §5 矩阵与 §6 分层）。

## 3. 测试协议（每模块三个测试）

设任务类 𝒯 = G′ 清单的行为判据集合（版本冻结于实验开始前）。

| 测试 | 问的问题 | 判据 |
| --- | --- | --- |
| **A 删除测试** | 指定层次删除后，哪些 G′ 判据失效？ | 失效集非空，且逐条给出失效机制 |
| **B 替代测试** | 其余组件能否在**同一架构内**重构该能力？ | 对 𝒯 行为等价 + 等价性论证（不是"看起来像"） |
| **C 反例测试** | 能否构造（或论证不存在）一个**不含该功能**的替代系统满足 𝒯？ | 构造出 → 非必要；论证不存在 → 必要性增强 |

**入选最小必要结构的标准**：A 显示能力损失 ∧ B 重构失败 ∧ C 反例不可构造。

与原表述的两点精化：

1. B 是**架构内可重构性**，C 是**替代架构存在性**——两者判据不同，不可合并；
2. 三测试依赖 𝒯 冻结；𝒯 若在实验中被修改，该轮结果作废重跑。

## 4. 第一轮：七次删除的逻辑推断（证据等级：推断）

| 删除 | 核心损失 | 初步判断 | 核对注记 |
| --- | --- | --- | --- |
| −S | 对象与状态锚定 | 必要（**能力级**） | 损失实为"锚定能力"；锚定可散在身份机制（ID 引用）中——必要性属能力，不必然属独立 S 模块 |
| −D | 依赖与影响传播 | 功能必要，实现方式开放 | 图结构 / 逻辑表达式 / 类型系统均可承载；层次见 §2.2 |
| −C | 约束与完成标准 | 功能必要 | 实现分两处：schema 字段 + 转移守卫（§5）；"什么算完成"可由数学定义/形式规范/实验协议共同实现 |
| −E | 证据输入 | 功能必要 | 数学证明本身属证据（与 RDE evidence 语义一致：`sufficiency`、外部验证引用） |
| −V | 可信度判定 | 功能必要且**最危险** | 实现侧最弱（F-E01：agent 可自我授予真值，已修）；E 与 V 必须区分：E 是证据本身，V 是对证据及其与命题关系的检查 |
| −T | 知识演化 | 必要（须拆两层） | 删日志 = 失去历史与回溯；删状态机 = 失去合法性。实验 6 只覆盖后者 |
| −Π | 自主研究决策 | 条件必要 | 判据不在 G′（自主性是运行模式属性，见 `capability_list.md` §5）；与 Phase 1 人驱动设计一致 |

**分层结论（初步）**：基础研究能力 S+D+C+E+V+T；自主研究能力 +Π。
但六模块是否不可约——**尚未排除功能包含关系**，进入第二轮（§8）。

## 5. 实现轨矩阵（证据等级：实现观察）

对现有代码（main @ 25882b1）的清点，作为消融的实证材料：

| 模块 | 实现位置 | 删除歧义 | 现状 |
| --- | --- | --- | --- |
| S | `fold` 视图（`core/engine.py`）+ 三维度状态（schema） | 视图 vs 维度语义 | 已实现；**是 T 的投影，非独立存储** |
| D | 边事件 + `core/dependency_analysis`（传播/路线聚合） | 边数据 / 关系语义 / 传播算法三层 | 已实现；路线独立性受 Q-007 限制 |
| C | schema（`proof_obligations`、`falsification_conditions`）+ 守卫 L1/L2/L3（engine/graph） | 字段 vs 守卫 | L3 已修；**L1 路线存在性未实现**（审计留档）、L2 未实现 |
| E | evidence 节点 + `sufficiency` + withdraw/invalidate 通路 | 节点 vs 通路 | 已实现（F-D01/D02 修复后） |
| V | **无独立模块**：schema 校验、引擎守卫、`verify_chain`、路线聚合、人工闸门、`external_validation_ref` | 分布式检查的总和 | **最危险又最未建成**；唯一外部锚钩子是 `external_validation_ref` |
| T | 事件日志（append + 哈希链）+ 状态机（转移规则） | 日志 vs 状态机 | 已实现；先写后应用的事务性问题见审计 F-A03（已以前置检查缓解，`_emit` 事务化仍待办） |
| Π | **不存在** | — | Phase 1 刻意人驱动（与"条件必要"判断一致） |

**三个反直觉观察**（实现轨第一轮产出）：

1. V 未成为模块——它散在守卫与校验中，且外部依据钩子只有一个字段；
2. Π 缺席——与阶段设计一致，消融实验对 Π 无对象可删；
3. S 是 T 的投影——实现给出的结构与七模块并列假设不同。

**实现轨实验的边界警告**：删除代码 + 跑测试 = 测量"我们的测试断言了什么"（R-019），
不是"研究需要什么"。实现轨只能证伪（测试没断言的能力确实丢了），
不能证实必要性——必要性论证必须回到 G′ 判据与 B/C 测试。

## 6. 分层假设（已登记 H-ABL-001）

候选分层：

- 研究表示层：S · D · C（对象如何形成结构与约束）
- 研究验证层：E · V（如何产生证据并接受检验）
- 研究演化层：T · Π（如何根据验证结果演化并决定下一步）

**两个未决问题（箭头语义）**：

1. 箭头指"定义上依赖于"还是"时间上先于"？——两者给出不同甚至相反的序：
   实现中 S = fold(T-日志)，定义上 T 在 S **之下**；
2. 运行时是环不是链：T 产生新 S 版本 → 新 C → 新 E → 再经 V → 再入 T。
   分层若是静态分解可以成立，若是动态时序则被环否定。

按登记规则入 `design_risks.md` §3：**H-ABL-001**（状态：假说）。

## 7. 映射条件（"双射"讨论的落点）

**全局双射不作为公理**。真实关系是多对多
（P → {O₁,O₂,O₃}，O₁ → {E₁,E₂}，一份证据可支持多个主张）。
需要的是**逐层映射性质**——实现现状恰好如此：

| 映射性质 | 条件 | RDE 已有对应物 |
| --- | --- | --- |
| 单射（身份不塌缩） | 不同对象不得合并为同一记录 | 节点/事件 ID 唯一性校验 |
| 满射（覆盖） | ∀o∈O_required, ∃e: supports(e,o) | L3：completed 前义务须全部履行 |
| 多对多（语义层） | 主张↔证据多对多 | `current_evidence` 引用、关系边 |

**两个开放点**：

1. L3 允许义务以 `withdrawn` 出场——"撤回即移出覆盖要求"是**策略选择**而非逻辑
   必然（关联 Q-008：撤回的授权边界）；
2. 覆盖条件中的 e 取什么？实现里 discharge 可经 decision/`external_validation_ref`
   而不附证据——**"覆盖"接受什么充当 e**，是方向 B 的第一个待答问题。

## 9. 与四个研究方向的关系

| 方向 | 内容 | 与本消融的关系 |
| --- | --- | --- |
| A 研究状态形式化 | 对象/命题/义务/证据/转移的定义 | §2 层次规范 + G′ 表达能力；对应 L1/L2 开放问题 |
| B 验证结构与可信性 | Agent 验证的独立性、可靠性、可追溯性 | §5"V 未成为模块" + §7 覆盖条件 + Q-007/R-017/R-023/原则 10 |
| C 研究状态压缩 | 海量历史 → 宏观状态（预测闭合） | 见下 |
| D 研究策略演化 | 下一步行动选择 | Π（未实现；条件必要） |

**方向 C 与 UCS 理论的闭环**（本轮讨论的核心发现）：

- X_t = 完整事件日志（"不删旧记录"纪律保证微观历史无损）；
- Z_t 候选 = fold 视图（当前状态、路线状态、义务状态）；
- 已知：Z_t 对**重放**充分（fold 确定性，Q-004 管辖）；
- 未知：Z_t 对**研究决策**是否充分——被撤回的反例、被发现的隐藏前提、被淘汰的
  路线，是否在某个未来决策点不可从 Z_t 恢复？（= 预测闭合条件，未证明）
- 代价所在：R-014 / Q-011（规模）。
- 即：**方向 C = 把 UCS 的微观→宏观预测闭合研究，用 RDE 当实验对象**；
  Gate 3 提供微观事件流，RDE 提供状态表示。
